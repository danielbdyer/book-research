## How this runs as a workflow

The phase structure above is the workflow's structure: phases 0–2 run as a short serial spine (record → re-ground → reconcile), phases 3–7 fan out per-task with per-file isolation (the seating and nit tasks are independent per note; the panel entries are independent per entry), phase 8 is a gated tail, and phase 9 is the serial close with the verification battery as its exit condition. Roughly: three serial stages, then a parallel middle of forty-to-sixty small tasks, then two serial stages. Every task's output is ordinary vault work — notes, rows, map lines — so a failed or interrupted run resumes by re-running its phase's verifier and continuing from what it reports. The author's veto surface during the run is this file plus the pull request diff; nothing in the run is destructive except the two file retirements in phase 9, both of which happen last, after verification passes.
