# plain-language lexicon

<!-- The single list of the vault's own coinages — words that are neither the book's vocabulary nor plain English — with what each one names in plain words. Opened 2026-09-03 at the author's request for a structural fix after a closing report was flagged as opaque. Three things read this table: scripts/queries/plain-scan.sh (which files still use a term with no plain referent anywhere in the file), .claude/hooks/plain-reply-check.py (whether the last reply of a turn used a hard term with no referent in the same reply), and any session repairing a file (which words to expand and how). Edit the table freely; the tools re-read it every run. The author has ruled that no regular expression finds a register fault, and that ruling stands: this list finds one fault class only, the bare coinage, which is the class the violations log shows recurring. -->

How to read the columns. **Term** is the coinage as it appears. **Matches** is the word-bounded, case-insensitive pattern the tools use. **What it names** is the plain-words referent a first use must carry. **Handling** is one of: *expand on first use* (the first appearance in a file or a reply carries the referent, later appearances may use the term), *replace* (never use the term; say the plain words), *name which* (the term is ambiguous between two vault things; say which). **Signature** lists short phrases; if any of them appears in the same file or reply, the tools count the term as expanded there. **Tier** is *hard* (rare in plain English, so a bare use is almost always a fault, and the reply check flags it) or *soft* (common in plain English, so only the file scan reports it and a person judges).
